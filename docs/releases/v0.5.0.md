# v0.5.0 - Observabilidad Completa

**Fecha:** 2026-09-24

## Objetivo

Completar la stack de observabilidad con trazas distribuidas y métricas mejoradas para External Secrets Operator.

## Cambios Realizados

### Tempo como Backend de Trazas

Añadido Tempo como backend de trazas distribuidas para completar la observabilidad:

- **Instalación:** Chart Tempo v1.11.0 en wave -10
- **Configuración:** Almacenamiento local para trazas (24h retención)
- **Recepción:** Soporte para OTLP gRPC y HTTP
- **Métricas:** Service-graphs y span-metrics habilitados

**Antes:** Las trazas iban al exporter `debug` del OTel collector (no persistían).
**Ahora:** Las trazas se almacenan en Tempo y pueden consultarse en Grafana.

### Integración con OTel Collector

Actualizado el OTel collector para enviar trazas a Tempo:

- **Exportador:** Cambiado de `debug` a `otlp` apuntando a Tempo
- **Endpoint:** `tempo-distributor.nullnode-observability.svc.cluster.local:4317`
- **Protocolo:** OTLP gRPC con TLS inseguro (local)
- **Pipeline:** traces → [memory_limiter, batch] → [spanmetrics, otlp]

### Grafana Integration

Configurado Tempo como datasource en Grafana:

- **Datasource:** Tempo añadido como datasource de trazas
- **URL:** `http://tempo-query.nullnode-observability.svc.cluster.local:3100`
- **Access:** Proxy (dentro del clúster)
- **Discovery:** Sidecar de Grafana descubre automáticamente

### Dashboards de Trazas

Creado dashboard de trazas en Grafana:

- **Nombre:** "NullNode Traces"
- **Visor:** Trace viewer de Tempo integrado
- **Query:** TraceQL para todas las trazas recientes
- **Refresh:** 10s
- **Scope:** Todas las trazas del clúster

### Dashboard de External Secrets Operator

Creado dashboard específico para External Secrets Operator:

- **Secret Sync Duration:** Tiempo de sincronización de secretos
- **Secret Sync Errors:** Errores de sincronización acumulados
- **Secret Requests:** Total de peticiones de secretos
- **Cache Performance:** Hits vs misses del caché de secretos

**Métricas:**

- `external_secrets_secret_sync_duration_seconds`
- `external_secrets_secret_errors_total`
- `external_secrets_secret_requests_total`
- `external_secrets_secret_cache_hits_total`
- `external_secrets_secret_cache_misses_total`

### Alertas de External Secrets Operator

Configuradas alertas de Prometheus para monitoreo de External Secrets:

- **ExternalSecretsHighErrorRate:** Error rate > 0.1/sec por 5m (warning)
- **ExternalSecretsSyncFailure:** Errores de sincronización > 0 por 10m (critical)
- **ExternalSecretsHighLatency:** Latencia p95 > 30s por 10m (warning)
- **ExternalSecretsCacheLowHitRate:** Hit rate < 50% por 15m (info)

## Ajustes Necesarios

### Exploración de Trazas

Tras el despliegue, familiarizarse con la interfaz de Tempo:

1. **Grafana:** Usar el datasource de Tempo para explorar trazas
2. **TraceQL:** Aprender sintaxis básica para filtrar trazas
3. **Service-graphs:** Explorar el gráfico de servicios generado por Tempo
4. **Span-metrics:** Ver las métricas derivadas de las trazas

### Ajuste de Retención

La retención actual es 24h. Ajustar según necesidades:

- **Mayor retención:** Aumentar `tempo.retention` y storage
- **Archivado:** Considerar configuración de archivado para trazas antiguas
- **Sampling:** Implementar sampling si el volumen es muy alto

### Ajuste de Alertas

Las alertas pueden necesitar ajuste tras el despliegue:

1. **Thresholds:** Ajustar según patrones de uso reales
2. **Severities:** Cambiar info/warning/critical según impacto
3. **Silencing:** Configurar silencios durante ventanas de mantenimiento
