# v0.6.0 - Chat UI works, teardown finishes

**Date:** 2026-10-02

## Goal

Close the two things left broken after v0.5.5: Open WebUI returned an error
instead of a chat, and `make down` reported success while leaving containers
running.

## Fixed

### Open WebUI could not start - a volume was hiding its own model cache

v0.5.5 gave Open WebUI a PVC and mounted it at `/app/backend/data`. That is
where Open WebUI keeps its SQLite database, so the mount point looked right.
It isn't: the image bakes the `sentence-transformers/all-MiniLM-L6-v2`
embedding model into `/app/backend/data/cache` at build time, and the image
sets `HF_HOME`, `SENTENCE_TRANSFORMERS_HOME`, `TIKTOKEN_CACHE_DIR` and
`WHISPER_MODEL_DIR` to paths underneath it.

Mounting an empty volume on the parent hid all of it. On startup Open WebUI
found no cached embedding model and tried to download it from HuggingFace -
which this platform's network does not allow - so it hung or errored before
serving a page.

The volume now mounts at `/app/backend/data/store` with `DATA_DIR` pointed at
it. The database persists, the baked cache stays visible, and nothing is
fetched at boot.

Two related defaults were also wrong for this deployment:

- **`ENABLE_OLLAMA_API`** defaults to `True`, so Open WebUI probes
  `http://localhost:11434/api` - an address nothing serves in that pod. All
  routing here goes through LiteLLM. Now `False`.
- **`OFFLINE_MODE`** is now `true`. It sets `HF_HUB_OFFLINE=1` and drops the
  version check, which suits a platform whose whole point is running without
  reaching out.

### `make down` left containers running and could hang

ArgoCD stamps `resources-finalizer.argocd.argoproj.io` on every `Application`
and on the `AppProject`. The teardown uninstalled the ArgoCD controller before
those finalizers were cleared, which left objects nothing could ever finalize.
Deleting the `argocd` namespace then blocked indefinitely, and because that was
the first phase, everything after it - the cluster, LocalStack, the volumes -
never ran. A `^C` out of the hang left the whole stack alive.

Three changes:

- **Finalizers are cleared first.** The cluster is about to be deleted
  wholesale, so orphaning what ArgoCD manages costs nothing.
- **Both destroys are time-bounded** (`tf_limited`, 600 s and 300 s). A destroy
  that stalls now surrenders instead of holding the rest of the teardown
  hostage.
- **A sweep phase runs last,** removing any `k3d-<cluster>-*` container, the
  LocalStack container and the cluster network that survived. Without it,
  `make down` could report success while the next `make up` tripped over the
  port bindings.

An incomplete platform destroy now also discards its state file. Every resource
in it - two Helm releases, three namespaces - lived inside the cluster, so a
half-written state only makes the next `make up` fail against things that are
already gone.

## Validation

`helm lint --strict` and `helm template` on all ten charts and both hardware
profiles; `shellcheck` on all eight scripts; `yamllint`, `markdownlint`, and the
Python and JSON checks.

The Open WebUI fix is reasoned from the upstream `Dockerfile`, `env.py` and
`config.py` at tag `v0.11.4` - the cache paths and the two env defaults are
quoted from source. It has not been confirmed against a running cluster.
