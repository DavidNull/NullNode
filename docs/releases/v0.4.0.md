# v0.4.0 - Security and Operations

**Date:** 2026-09-22

## Goal

Complete security hardening and improve automated platform operations.

## Changes Made

### Progressive NetworkPolicies

Enabled NetworkPolicies on main components following the progressive approach
recommended in GOTO.md:

- **Redis:** Enabled in v0.3.1
- **Postgres:** Enabled in v0.4.0
- **LiteLLM:** Enabled in v0.4.0
- **Ollama:** Enabled in v0.4.0 (new template created)

**Validation:**

- Helm lint and template validation pass for all components
- Full platform validation for GPU and CPU profiles
- NetworkPolicies restrict traffic to authorized namespaces only

### Reloader for Automatic Rotation

Completed the External Secrets Operator flow by adding Reloader:

- **Installation:** Reloader operator added in wave -15
- **Configuration:** ServiceMonitor enabled for Prometheus integration
- **Annotations:** Added `secret.reloader.stakater.com/reload` annotations on:
  - LiteLLM deployment (secrets: litellm, postgres, redis)
  - Postgres StatefulSet (secret: postgres)
  - Redis StatefulSet (secret: redis)

**Benefit:**

- Automatic credential rotation without manual intervention
- Pods restart automatically when External Secrets Operator updates a secret
- Completes the flow described in ADR-0007

### Presidio Enabled on GPU

PII guardrail enabled by default on GPU profile:

- **Configuration:** `presidio.enabled: true` in `values-gpu.yaml`
- **Expected impact:** ~2 GiB additional RAM and latency on requests
- **Monitoring:** Real impact should be measured after deployment

**Note:** The component was already wired in the platform, just disabled due to
resource consumption.
