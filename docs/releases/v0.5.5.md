# v0.5.5 - Stable

**Date:** 2026-09-30

## Goal

Make a first deployment succeed on a clean machine. Every change here fixes
something that was already broken, rather than adding surface.

## Fixed

### Model pulls were denied by the cluster's own NetworkPolicy

Ollama's NetworkPolicy declared `policyTypes: [Ingress, Egress]` and then
allowed exactly two things outbound: UDP/53 and LiteLLM on port 4000. Nothing
permitted `registry.ollama.ai:443`. k3s runs a NetworkPolicy controller by
default, so `ollama pull` in the `preload-models` init container was denied at
the CNI on every deployment. It read as a network problem on the host, which is
where the time went.

The egress rules now cover:

- **DNS over TCP as well as UDP.** A truncated answer is retried over TCP, and a
  silent failure there is indistinguishable from the registry being down.
- **TCP 443 and 80 to public addresses,** with RFC1918 ranges excluded. Pulls
  work; nothing inside the cluster is newly reachable.

The unused egress rule to the gateway is gone. Ollama never calls LiteLLM - the
traffic runs the other way.

### A failed pull produced a pod that looked healthy

v0.5.2 made pull failures non-fatal, so the pod started with no weights, passed
its readiness probe, and failed on the first real request as a 500 from the
gateway - a long way from the cause.

Each pull now retries five times with increasing backoff. If it still fails the
init container exits non-zero and the pod stays in `Init`, where the reason is
visible in one `kubectl logs`.

### Open WebUI could never start

The chart read the gateway key from `nullnode-litellm-credentials` under the key
`master_key`. External Secrets creates that Secret with `master-key`. The
key does not exist, so the pod stayed in `CreateContainerConfigError` - on the
GPU profile, where Open WebUI is enabled by default.

Also corrected while it was open:

- **Replica count.** Ran with two replicas over an ephemeral SQLite database:
  each replica had its own users and chats, and each rejected the other's
  session tokens. Now one replica with a 4 GiB PVC.
- **Session key.** `WEBUI_SECRET_KEY` was unset, so it was regenerated per pod
  start and logged everyone out on every rollout. Now sourced from the same
  Secret.
- **Update strategy.** `RollingUpdate` with `maxSurge: 1` against a
  ReadWriteOnce volume; changed to `Recreate`.
- **PodDisruptionBudget.** `minAvailable: 1` on a single replica blocks every
  node drain. Now rendered only above one replica.
- **ServiceMonitor.** Scraped `/metrics`, which Open WebUI does not serve - a
  permanently down Prometheus target. Removed.
- **Image tag.** Was `main`, against a repository whose policy is to pin
  everything. Now `v0.11.4`.
- **Reloader.** Added the annotation so a rotated gateway key reaches the UI.

### Pinned versions that nothing verified

`make versions-check` checked seven charts. Tempo (1.11.0) and Reloader (1.0.67)
are pinned in `k8s/platform/values.yaml` but were missing from the list, despite
the comment telling the reader to keep the two in step. Both added, along with
the Open WebUI image and the three missing charts in `VERSIONS.md`.

## Documentation

- **`make up --from cloud-mock`** appeared four times in `TROUBLESHOOTING.md`.
  Make takes no such flag; it is `./scripts/up.sh --from cloud-mock`.
- **A secret that does not exist.** The 401 section pointed at
  `litellm-master-key`; the Secret is `nullnode-litellm-credentials`.
- **"No chat UI"** in the README was false on the GPU profile, which has shipped
  Open WebUI enabled since v0.4.0.
- **The request flow** was stated twice in the README, verbatim.
- **`make hosts`** omitted `chat.<suffix>`, so the chat UI resolved for nobody
  who followed the instructions.
- **`make netpol-on`** printed instructions for enabling NetworkPolicies that
  have been on since v0.4.0. Removed.
- **`.trivyignore`** comments cited rule IDs that were not the ones listed under
  them.
- **New troubleshooting entries** for a blocked model pull and for WSL2 losing
  outbound DNS, with the host, node and pod checks in order.
- **v0.5.1 and v0.5.2** have release notes for the first time, including a
  correction: the v0.5.1 notes described a Tempo Ingress and two NetworkPolicies
  that were never written. They are now tracked in `GOTO.md`.

## Housekeeping

Removed three unreferenced images and renamed two to English, matching the
kebab-case of the rest: `mockeado.png` to `aws-mocked.png` and
`nullnode_arch_final.png` to `nullnode-architecture.png`.

## Validation

`helm lint --strict` and `helm template` pass on all ten charts and on both
hardware profiles.
